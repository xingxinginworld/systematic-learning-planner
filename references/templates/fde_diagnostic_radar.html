🗺️ 一、FDE 到底是干嘛的？

用一句话说清 FDE

FDE = Forward Deployed Engineer，Palantir 造的词。业内也叫交付工程师 / 解决方案工程师。

🎯 大白话定义
一个能自己下场写代码的项目经理，或者说一个懂业务的工程师。他要去客户现场，把客户的模糊需求变成能跑起来的系统，还得让客户会用、用得爽。

跟你熟悉的角色比一比

角色主要战场关键能力谁负责最终结果
PM（你现在）会议室 / 需求文档沟通、拆解、协调项目按时上线
开发工程师IDE写代码、调 bug代码质量、性能
解决方案架构师PPT / 白板画架构图、选型方案技术合理性
FDE（你要变成的）客户现场 + IDE懂业务 + 能动手改端到端交付效果

💡 你要记住的核心结论
FDE 是端到端的负责人。他不是"写更好的代码"，而是"让整条链路真的跑起来、真的解决业务问题"。你 PM 的经验，正好覆盖了链路两头（摸需求、管交付）；要补的是中间那三段（搭原型、让它稳、接数据）。

🧭 二、FDE 七项能力（业务语言版）

下面这七项能力，是我把 FDE 拆解后形成的模型。每项都用"你 PM 时怎么用它"来对照，方便你评估自己的起点。前六项覆盖通用 FDE 场景，第 ⑦ 项是政企驻场专属——如果你要做金融/电力/政务/央国企类项目，这一项决定你能不能真正把系统落地。

1
懂业务
你的强项

干什么：听懂客户到底要啥，识别他表面话和真痛点的差距，判断这活能不能用 AI 干。

PM 时怎么用：你写 PRD 前要访谈、要画业务流程图、要挖用户 story。这些技能可以直接搬。

FDE 要额外会：多一个判断——"这个需求 AI 到底适不适合做、值不值得做"。有些需求硬上 AI 是灾难。

2
会翻译
升级项

干什么：把业务需求翻译成技术方案。选架构（工作流 / RAG / Agent / Multi-Agent）、估成本、算 token 账、画数据流图。

PM 时怎么用：你写过技术方案文档，知道要跟开发对齐术语。

FDE 要额外会：你自己要能画出 Agent 架构图，不能只依赖开发讲给你听。

3
搭原型
核心新技能

干什么：1 小时验证一个假设，3 天搭一个能演示的 Demo。会调 LLM API，会写 Prompt，会用 Function Calling，会搭简单 RAG。

PM 时怎么用：基本没用过。你以前是"提需求，等开发交付"。

FDE 要额外会：这是最大的技能跨越——从"能说不能做"到"能自己搭出来给客户看"。

4
改得动
核心新技能

干什么：Demo 有 bug 能自己看日志定位。Prompt 效果不好能自己调。小改动不用等开发。看得懂开发的代码。

PM 时怎么用：基本没用过。你以前是"发现问题→提工单→等修复"。

FDE 要额外会：从"发现问题"到"能自己动手改小问题"。Git 基本操作、代码 review 基础、调参数、改 prompt。

5
管交付
你的强项

干什么：拆里程碑、识别风险、写验收标准、管客户预期、上线前逐条过 checklist。

PM 时怎么用：你的看家本领。项目管理三件套：计划、跟踪、复盘。

FDE 要额外会：AI 项目的验收标准跟传统软件不一样，要覆盖 Bad Case、评估指标、SLA 这些新东西。

6
善沟通
你的强项

干什么：对客户老板讲价值，对业务专家讲工作原理，对开发讲需求，主持跨角色对齐会。

PM 时怎么用：你的看家本领。翻译官+粘合剂。

FDE 要额外会：多一个"技术翻译"角色——把 AI 系统的原理和限制讲给业务方听懂。

7
啃环境（政企环境适配）
驻场专属

干什么：让 Agent 在客户真实环境里活下去——内外网隔离、防火墙白名单、代理跳转、堡垒机、离线部署、等保合规、数据脱敏。你的 Demo 在办公室跑得好好的，客户机房里可能连一个 API 都调不通。

PM 时怎么用：驻场过就知道，政企环境跟公有云完全不是一回事——内网独立、访问要审批、部署要走变更单、数据不出网。你有感性认识，但可能没系统梳理过。

FDE 要额外会：能在方案设计阶段就预判环境坑（哪些 API 通不了、哪些数据不能上云、哪些依赖装不上），并提前给出可落地的替代方案（本地部署 / 私有模型 / 反向代理 / 离线依赖包）。不能只在自己电脑上跑通，要能预判客户环境的坑。

🧩 七项能力的组合逻辑
① ⑤ ⑥ 是业务闭环（懂 → 管 → 传），你已经跑通。② 是桥梁，③ ④ 是技术闭环（搭 → 改），你要新学。⑦ 是落地闭环——政企场景专属的"最后一公里"，很多技术过硬的团队栽在这项上。补齐 ② ③ ④ + ⑦，你就从 PM 升级成 FDE。

✅ 五、完成标志 & 验证方式

今天这个自评不是"填完就完"，它是你后面学习路径的基线。下面这套验证方法，确保你今天做的这份评估是可用的。

1. 完成度校验（4 条必做）

  • 35 题全部作答完，不留空
  • 点了"生成雷达图"，看到了七边形
  • 能不看纸说出：你最强的 3 项和最弱的 3 项分别是啥
  • 把结果文本复制发给我（用于路径调整）+ 雷达图截图保存到本地

2. 诚实度自检（防止虚高 / 虚低）

⚠️ 三个反问，问完再确认得分

问自己：对你打了 4-5 分的每一项，能立刻举出 3 个真实工作案例吗？举不出来说明高估了，调回 3 分。

问自己：对你打了 1-2 分的每一项，能说出"上次踩坑是什么场景"吗？说不出来可能是没意识到该场景存在，不代表你做不好。

问自己：你 35 题的得分标准差是多少？如果差异特别小（都填 3），说明你没认真思考，重做一遍。

3. 稳定性验证（一周后重测）

🔁 一周后同一份问卷再做一次
如果两次分数差异都在 ±0.5 以内，说明这次评估是可信的。如果差异 > 1 分，说明第一次没认真评，以第二次为准。

4. 学习期间的复盘节奏

时机做什么看什么
Day 0（今天）首测知道起点
Phase 2 结束搭原型阶段完成后重测③ 搭原型 应该有明显提升
Phase 3 结束让 Agent 可用阶段后重测④ 改得动 应该有明显提升
Phase 4 结束政企环境适配阶段后重测⑦ 啃环境 应该有明显提升
结营终测七项分数应该都 ≥ 3.5

5. 结果异常时怎么办

🚨 三种"结果不可用"信号

信号 A · 全部分数一样：你没认真评，或对自己没画像。→ 重做，或找信任的同事帮你评一遍。

信号 B · 已有强项 ①⑤⑥ 得分 < 3：你在 PM 这行都还没稳，先补 PM 基本功再学 FDE。

信号 C · 新技能 ③④⑦ 全 5 分：你已经会了，不需要学 FDE，直接找项目实战。
