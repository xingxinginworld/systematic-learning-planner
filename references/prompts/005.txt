# Step 005 · 每日内容生成（Daily Lesson）
> 用途：为每节产出 6 板块交互式 HTML 学习内容
> 输入：004 路径目录 · 006 周/日计划 · {内容类型}
> 输出：自包含 HTML（目标 / 讲解 / 动手 / 速查 / 测验 / 金句）
> 依赖：006（执行拆解）→ 本步 → 007（总复习）

基于已确认的学习路径目录与当周/当日计划，现在请为下面的小节生成一份「每日学习内容」。

- 所属章节：{例如：第 1 章 工程底座：环境与 TypeScript}
- 小节编号及标题：{例如：1.2 环境与 TypeScript 基础}
- 当日目标（来自周/日计划）：{填入当日要达成的 3-5 个目标}
- 内容类型（由主题自动判断，或用户指定）：IT/AI/编程类（动手需含代码） / 非技术类（理论·商业·人文·语言·软技能等，动手用适配形式）

## 输出要求（务必达标）

**格式**：生成一份**自包含的交互式 HTML**（内联 CSS/JS，不依赖外部 CDN），直接复用 skill 的 `references/templates/day_content_template.html` 作为结构与样式基准——先打开它看"达标长什么样"，再按下面 6 个板块的骨架产出，保持一致的视觉组件（hero / card / box / mentor / mnemonic / steps / case-block / cheatsheet / quiz-item / interview-quote）。

**必须包含且顺序固定的 6 个板块**（与模板一一对应）：

1. **🎯 一、今日目标** — 3-5 个可测量目标（"能够…/理解…/掌握…"），开头用「导师说」mentor 卡片点明本节在全局路径里的位置与动机。
2. **📖 二、核心讲解** — 用「是什么 / 为什么 / 怎么用」三段组织；配 box 要点卡（蓝=行动指南、红=常见坑、黄=顺序提醒、紫=对外话术）、mnemonic 口诀卡、steps 编号步骤。每个概念给一句人话解释 + 一个真实示例。
3. **🛠️ 三、动手步骤** — 至少 1 个「跟着做」的真实 Case Study + 2 个「自己练完看答案」的 case（答案折叠在 `<details>` 里）。实操形式**按内容类型适配，切勿对非技术主题硬塞代码**：
   - **IT / AI / 编程类**：含可运行代码片段 + 量化指标前后对比表（虚构路径/密钥用占位符）。
   - **非技术类**（理论/商业/人文/语言等）：改用贴合主题的实操形式——真实案例分析、决策/权衡演练、模板或清单填写、方案/短文撰写、角色扮演对话、计算或应用题等；同样要明确「做对/做错」或「优劣判定」标准，避免空谈。
4. **📇 四、速查卡** — 1-3 张 cheatsheet（对照表 / 参数速查 / SOP 清单），以表格呈现，可直接打印或截图存。
5. **📝 五、5 题小测验** — **纯选择题（A/B/C/D）**，每题 `<details>` 折叠，展开后含「✅ 答案」+「❌ 错项解析」（错项解析比答案更值钱）。题目覆盖当日全部目标。
6. **💼 六、面试金句预埋 / 心得笔记** — 2-3 条 interview-quote（可直接用在求职/客户汇报的口语化金句）+ 1 张「今天最反直觉的 N 件事」red box。

**质量红线**：
- 目标必须可测量，不讲空话；概念必有示例；**动手案例的实操形式按内容类型适配**（IT/AI/编程类给可运行代码；非技术类给案例分析/决策演练/模板填写等，同样要可操作、有判定标准）；测验必有解析。
- 受众视角：默认面向「有交付经验、需补技术」的成年人（参考 FDE 示例的 PM 视角），多给"对客户怎么说/汇报口径"的提示。
- 替换模板里的 FDE 专属文案（标题、subtitle、hero-meta、案例主语、footer 的 Day N）为当前主题的真实内容；跨日导航用占位符 `【上一日主题】`/`Day 【N+1】`。
